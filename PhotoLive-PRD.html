01背景与目标

问题不在“能不能看到照片”，而在“照片到达客户手里的链路太长，挑片又靠口头沟通”。

现场拍摄 → 照片留在摄影师设备 → 导出到电脑 → 上传网盘 / 微信发送 → 客户等待并下载 → 客户口头描述“第几张” → 摄影师人工筛图 → 再发一次

一次活动至少两次文件搬运、两轮沟通，且客户在最有热情的现场时段看不到照片。

产品决策

把“交付”和“选片”合并进拍摄现场同一个链接：摄影师建一个活动房间，照片上传完成即可见；客户免注册扫码浏览并标记喜欢的照片；标记结果以文件名清单的形式回到摄影师，直接用于修图软件筛选。

预期结果（可观察，不设虚构指标）

  • 客户全程不需要安装应用、不需要注册账号，只凭链接和访问码完成浏览、挑片、下载。
  • 客户完成挑片后，摄影师无需再问“你要哪几张”，直接获得带原始文件名的选中清单。
  • 一场活动的上传动作只发生一次，后续交付与挑片都由同一个房间承载。

02角色与核心对象

全局只有两个真实角色，客户完全免注册——这是本产品最重要的信任设计。

角色

角色身份方式职责不能做的事
摄影师邮箱 + 密码登录创建房间、上传照片、删除照片、查看选中结果、导出清单、结束房间不能代替客户标记照片
客户 / 访客房间链接 + 访问码，免注册浏览展示墙、标记 / 取消标记、下载自己选中的照片不能上传（P0）、不能删除、不能看其他房间

核心对象

对象定义关键属性生命周期
房间一次活动的照片集合，是分享和权限的最小单位名称、活动日期、访问码、是否允许下载、状态、创建时间进行中 → 已结束 → 已删除
照片一张原始文件及其派生缩略图原文件名、拍摄时间、上传时间、处理状态、上传者角色处理中 → 可看；处理中 → 失败
标记某位客户对某张照片的选中关系访客标识、照片、标记时间未选 ↔ 已选；房间结束后冻结
选中清单由标记派生的导出结果，不单独持久化原始文件名、拍摄时间、标记时间每次导出即时生成
信任边界：房间链接 + 访问码就是客户的全部凭证。产品不承诺企业级权限控制；摄影师通过“重置访问码”和“结束房间”控制访问范围。

03范围边界

P0 只保证一条最小完整旅程跑通，其余能力明确后置。

P0 最小完整旅程

摄影师 登录→ 创建房间→ 批量上传→ 看选中结果→ 导出清单→ 结束房间
客户 扫码→ 输访问码→ 浏览展示墙→ 标记喜欢的→ 下载已选

P0 内的关键判断

能力决策与理由
客户下载P0 支持下载“自己标记过的照片”原图（ZIP）。客户挑完必须能把图拿走，否则闭环仍断在“再等摄影师发一次”。水印、限次、防盗链属于 P1。
HEIC / HEIFP0 支持。iPhone 摄影师与客户大量使用 HEIC，不处理会直接导致“打开是裂图”。服务端统一转为 JPG 后保存、预览与下载（不再单独保留 HEIC 原文件，避免下载到无法打开的图片）。
上传端P0 只做 Web：电脑浏览器拖拽批量上传优先，手机浏览器可上传。不做原生 App / 桌面客户端。
实时性P0 做页面内自动更新：已打开的页面在数秒内出现新照片，不做系统推送、短信、邮件通知。
访客上传P1 已实现：房间默认关闭，摄影师可在房间详情开启；客户上传的照片标注来源，摄影师可删除。

P0 明确不做

水印与防盗、付费与套餐、人脸聚类找自己、原生 App、多摄影师协作、在线精修下单、评论点赞、长期归档。

P1 候选

预览图水印、下载次数限制、照片点赞与评论、AI 按人脸/场景聚类、多客户分组选片、精修加购。

04核心流程

一个房间从创建到结束的完整时序，以及客户侧的三步动作。

阶段摄影师动作客户可见状态系统行为
T0 建房填写名称、日期，生成房间—（尚无链接可分享）生成访问码、房间链接与二维码
T1 上传拖入一批照片已进入页面的客户看到“处理中”占位逐张上传 → 转码缩略图 → 可看
T2 分享把链接/二维码发给客户输入访问码进入展示墙校验访问码，建立访客会话
T3 挑片继续补传照片边看边标记，底部实时显示已选数量标记即时保存，摄影师侧同步计数
T4 收口查看选中结果并导出清单可下载已选原图按文件名生成 ZIP 与 CSV
T5 结束结束房间只读，不能新增标记，仍可下载冻结标记，进入保留期
关键约束：客户在 T3 期间不需要摄影师做任何操作。摄影师补传照片时，客户页面必须自动出现新图，不能要求客户刷新或重新输码。

FR-01 摄影师账号与登录 P0

让房间和照片有明确归属，同时把客户的注册成本降为零。

触发与入口

首次使用进入摄影师后台；登录态过期后再次访问房间管理页。

处理规则

  • 注册字段：邮箱、密码。密码至少 8 位，需同时包含字母与数字；邮箱全局唯一。
  • 不做邮箱验证、短信验证、第三方登录（单实例部署，不依赖外部服务）。
  • 登录态保持 7 天；主动退出立即失效。
  • 连续 5 次密码错误，该账号锁定 15 分钟。

结果与状态变化

登录成功进入“我的房间”列表，展示房间名称、日期、照片数、已选数、状态与新建入口。

异常

  • 邮箱已注册：提示“该邮箱已注册，请直接登录”。
  • 密码错误：统一提示“邮箱或密码不正确”，不区分具体原因。
  • 账号锁定：显示剩余锁定时间，倒计时结束后可重试。

FR-02 创建与管理活动房间 P0

房间是分享单位，客户拿到的是“一个房间”，而不是一堆散图。

字段

字段必填规则
房间名称是2–40 字，用于客户页面标题
活动日期是默认当天，可改；仅用于展示与列表排序
访问码是系统生成 6 位数字；可改为 4–8 位字母数字；进行中的房间内唯一
允许客户下载是默认开启；关闭后客户只能看与标记，下载入口隐藏
备注否≤200 字，仅摄影师可见

处理规则

  • 创建成功即生成房间链接与二维码，可一键复制链接、保存二维码图片。
  • 访问码可重置；重置后旧码立即失效，已进入的客户会话不被强制踢出。
  • 房间数量不限制，列表按活动日期倒序排列。

结果与状态变化

房间进入“进行中”，可上传照片。点击“结束房间”需二次确认，结束后转为只读。

异常

  • 访问码被占用：提示更换，不自动顺延。
  • 删除房间：必须输入房间名称确认，照片、标记与文件一并删除且不可恢复。
  • 重复提交创建：同一次提交只生成一个房间。

FR-03 照片上传与处理 P0

把“摄影师传得动、传得完整”作为第一优先级，任何失败都不能拖垮整批。

触发与入口

房间详情页“上传照片”。支持拖拽到区域、点击选择文件、一次选择多个文件。

限制

项目规则
格式jpg / jpeg / png / heic / heif / webp；其他格式拒绝并列出文件名
单张大小≤50MB [Assumption, TBD]
单次数量≤300 张 [Assumption, TBD]；超出提示分批上传
单房间总数建议 ≤3000 张 [Assumption, TBD]；超出提示新建房间

处理规则

  • 逐张上传，客户端并发 3 个任务；每张独立进度，单张失败不影响其他照片。
  • HEIC / HEIF 自动转为 JPG 用于预览与下载；为保证客户在任何设备都能打开，仅保留转换后的 JPG。
  • 服务端生成两档缩略图：列表用 480px、全屏预览用 1600px；处理完成前该照片在展示墙显示“处理中”占位。
  • 重复判定：同一房间内“原文件名 + 文件大小”均相同视为重复，默认跳过，上传结束后汇总提示。
  • 同名不同内容：存储名追加序号，展示名同步追加序号并提示，避免导出清单时撞名。
  • 排序时间取 EXIF 拍摄时间；缺失时取上传时间。时区原样使用，不做换算。

结果与状态变化

照片处理完成后立即可见，房间详情的照片数与客户的展示墙同步增加。上传者是摄影师本人时标记为“摄影师”。

异常

  • 磁盘空间不足：阻止本次上传并提示剩余空间，已成功的照片保留。
  • 网络中断：已完成的照片不回滚，未完成项显示“重试”。
  • 图片处理失败：照片标记为“失败”，可单张或批量重新处理；失败照片不进入客户展示墙。

FR-04 客户展示墙 P0

客户在手机上第一眼就要看到“刚拍完的照片”，而不是“一个等待下载的网盘”。

触发与入口

客户打开房间链接。无访问码链接直接进入；带码链接需先输入访问码。

处理规则

  • 首次进入需输入访问码；同一浏览器后续访问不再重复校验。
  • 访问码连续错误 5 次，该浏览器锁定 10 分钟。
  • 自适应网格：手机 2 列、平板 3 列、桌面 4 列；点击进入全屏预览，可左右滑动切换。
  • 默认按拍摄时间正序，支持切换倒序；切换不影响已标记状态。
  • 列表只加载缩略图，滚动懒加载；全屏才加载 1600px 预览图。
  • 页面已打开时，新照片在 3 秒内出现，顶部提示“新增 N 张”，点击回到顶部 [Assumption, TBD]。
  • 不展示 GPS 等位置信息，只展示拍摄时间。

结果与状态变化

客户可浏览、标记、下载。房间结束后顶部出现“活动已结束，仅供查看”提示，标记按钮冻结。

异常

  • 空房间：显示“摄影师正在上传，请稍等片刻”，并自动等待新照片。
  • 加载失败：单张显示重试占位，不阻塞其他照片。
  • 访问码错误：提示剩余尝试次数；房间不存在或已删除时提示“房间已失效”。

FR-05 客户选片标记 P0

把“第几张、那个穿蓝衣服的”变成一次点击，并且不需要提交按钮。

触发与入口

客户在网格或全屏预览中点击照片右下角的选择按钮。

处理规则

  • 点击即切换选中 / 取消，即时保存，无“提交”动作。
  • 同一客户对同一照片只保留一条标记；重复点击等价于取消后再选中。
  • 底部固定条显示“已选 N / 共 M”；切换“只看已选”后仍显示全量计数。
  • 客户首次进入房间时，浏览器本地生成访客标识；同一浏览器刷新、再次进入均保留标记。
  • 换设备、换浏览器或清除浏览器数据后，标记不恢复 [Assumption, TBD]。
  • 摄影师不能代替客户标记；标记不展示客户身份（P0 默认单客户场景）。

结果与状态变化

标记即时反映在客户底部计数和摄影师房间详情的“已选”数量上；照片可被下载的前提是“已标记”。

异常

  • 标记的照片已被摄影师删除：提示“该照片已被移除”并刷新网格。
  • 保存失败：界面先本地生效，后台自动重试 3 次；仍失败则回滚并在照片上提示重试。
  • 房间已结束：标记按钮置灰，点击提示“活动已结束，无法修改选择”。

FR-06 客户下载已选照片 P0

让客户挑完就能直接拿走，避免“挑完还要再等一次发送”。

触发与入口

客户端底部“下载已选”。房间未开启“允许客户下载”时不显示该按钮。

处理规则

  • 只打包已标记照片的原图（HEIC 已转 JPG 的按转换后文件提供），生成 ZIP。
  • ZIP 内文件名保留原始文件名；重名文件使用上传时追加的序号。
  • 打包在服务端后台执行，关闭页面后任务继续，重新进入可下载已完成文件；下载链接一次性有效。
  • 未标记任何照片时按钮置灰。

结果与状态变化

生成一次性下载链接，下载行为不改变标记状态。

异常

  • 打包失败：提示重试，不清空标记。
  • 磁盘空间不足：提示稍后重试，并告知摄影师侧需要清理空间。
  • 房间已删除：下载入口失效，提示“房间已失效”。

FR-07 摄影师查看与导出选中结果 P0

交付物必须是修图软件能直接用的东西——文件名，而不是截图。

触发与入口

房间详情页显示“已选”统计；点击进入“仅看已选”视图；点击“导出清单”。

处理规则

  • “仅看已选”展示被标记照片的缩略图、原始文件名、拍摄时间、标记时间。
  • 导出格式：CSV（原始文件名，拍摄时间，标记时间）与 TXT（每行一个原始文件名）。
  • 文件名含逗号或引号时，CSV 使用标准引号转义，避免修图软件读取错列。
  • 客户标记后，摄影师端在 5 秒内更新数量与列表 [Assumption, TBD]。
  • 不展示客户身份信息；多客户分组选片属于 P1。

结果与状态变化

导出生成即时文件，不改变房间状态；无标记时导出按钮置灰并提示“还没有客户选中照片”。

异常

  • 导出过程中标记发生变化：以导出那一刻的结果为准，并在文件名中附带时间戳。
  • 照片已被删除：自动从清单剔除，不生成空行。

FR-08 房间结束与数据保留 P0

给房间一个明确的终点，避免“永远开着、越存越多”。

触发与入口

摄影师在房间详情点击“结束房间”，二次确认后生效。

处理规则

  • 结束后：客户页面只读，不能新增或取消标记；仍可浏览、仍可下载已标记照片。
  • 默认保留 30 天 [Assumption, TBD]，到期后原图与缩略图删除，仅保留房间记录与标记统计。
  • 摄影师可在结束后立即删除房间；删除需输入房间名称确认，不可恢复。
  • 结束操作可逆（重新开启）[Assumption, TBD]，重新开启后客户可继续标记。

结果与状态变化

房间状态变为“已结束”，列表中以灰色标识；客户页面顶部出现结束提示。

异常

  • 删除时仍有客户在浏览：该客户下次操作收到“房间已失效”。
  • 删除时正在打包下载：打包任务终止并提示失败。

FR-09 访客上传 P1 已实现

把“同行互传”并入同一个房间，让摄影师不再是唯一的上传入口。

触发与入口

房间开启“允许访客上传”且状态为进行中时，客户相册页顶部出现“＋ 上传”。

处理规则

  • 默认关闭，由摄影师在房间详情中随时开启或关闭；关闭后接口直接拒绝上传。
  • 客户上传与摄影师上传共用同一套格式、大小、去重、缩略图与排序规则。
  • 访客照片进入同一展示墙，按拍摄时间排序，上传者标记为“guest”。
  • 摄影师在照片网格中看到“访客”角标，可删除任何访客照片；删除后对应标记一并移除。
  • 访客不能删除照片，也不能向未开启开关的房间上传。
  • 可开启“访客照片需审核”：访客上传后进入待审核区，摄影师逐张“通过/拒绝”，仅通过的照片进入客户相册；拒绝会删除照片。

结果与状态变化

上传成功后照片立即出现在所有已打开页面；开启审核时，访客照片先进入待审核区，通过后才展示。房间结束后上传入口隐藏，接口返回“活动已结束”。

异常

  • 未开启开关：403“摄影师未开放访客上传”。
  • 重复文件：与摄影师上传一致，跳过并提示。
  • 达到房间上限：409，提示新建房间。

6.3 命名与去重（唯一定义）

  • 展示名与导出名一律使用原始文件名。
  • 同房间同名不同内容：追加序号，格式为 原名_2.jpg，上传完成时提示摄影师。
  • 同房间同名且同大小：判定为重复，跳过并计入“已跳过”统计。
  • 存储内部分名与展示名解耦，任何内部重命名都不改变客户与摄影师看到的文件名。

6.4 时间规则

  • 排序与展示用拍摄时间（EXIF）；缺失时用上传时间。
  • CSV 中的时间格式统一为 YYYY-MM-DD HH:mm，不附时区。
  • 活动日期只影响房间列表排序，不影响照片排序。

07已确认技术约束

本节只记录已确认的选型及其对产品行为的约束，不展开实现方案。

层已确认选择对产品的影响
后端Go单二进制部署，适合单实例 + 本地磁盘形态
数据库SQLite 默认，可切换 MySQL两种数据库下产品行为必须一致；并发写入能力受 SQLite 限制，标记写入需轻量
文件存储本地文件存储，预留 OSS 存储桶适配下载链接形态在本地与 OSS 下不同，页面不暴露具体存储地址；容量上限受本地磁盘约束
前端Tailwind CSS + 原生 JavaScript，自适应 H5单一响应式页面同时服务客户手机与摄影师桌面；不引入前端框架
HEIC 转换依赖服务器上的 ffmpeg / ImageMagick / heif-convert，可用 PHOTOLIVE_HEIC_CONVERTER 指定未安装转换器时 HEIC 上传返回明确错误，不影响 JPG / PNG / WebP
外部服务不依赖邮件、短信、推送无邮箱验证、无自助找回密码、无系统通知；实时性只能依赖页面内更新
约束结论：“无外部服务”与“单实例”决定了 P0 必须放弃账号找回、消息通知与多实例横向扩展；这些能力一旦要做，需要先引入相应基础设施。
